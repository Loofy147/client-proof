# Client Proof

A curated public evidence surface for paid engineering work.

This repository is intentionally separate from internal research and proposal operations.

## Purpose

Show a client, in a few minutes:

1. the problem class we can address;
2. the concrete artifact delivered;
3. what was actually verified;
4. the evidence and limits;
5. the scope of a corresponding paid engagement.

This is not a dump of internal work, conversation history, experiments, or unfinished research.

## Proof contract

Every published proof should expose:

- **Problem** — the concrete problem class.
- **Outcome** — the artifact or result produced.
- **Implementation** — the relevant technical surface.
- **Verification** — what was actually executed or checked.
- **Evidence** — links to source, tests, CI, or receipts.
- **Limits** — what the proof does not establish.
- **Commercial scope** — the bounded service that can be delivered.

## Evidence policy

A proof is published only at the strongest status supported by actual evidence.

We do not present:
- portfolio prototypes as customer deployments;
- generated claims as execution evidence;
- tests that were not actually run as passing tests;
- capabilities that depend on an unavailable environment as already delivered.

## Internal separation

Research, proposal strategy, prospect tracking, and unfinished architecture remain in separate private/internal repositories.
